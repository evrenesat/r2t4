# RALF Handoff Plan: Config-Driven Pipelined Scene Analysis

## Project Done

- [ ] The pipeline is driven by one versioned TOML file at `config/pipeline.toml`, not stage-specific CLI knobs.
- [ ] Model/backend choice is alias-driven for three independent roles: `subtitle_summary_model`, `scene_analysis_model`, and `artifact_model`.
- [ ] Subtitle acquisition starts as early as possible during extraction, and per-grid subtitle summaries are generated by a capable model as soon as subtitle events and chunk windows are available.
- [ ] Scene-image inference uses precomputed subtitle summaries plus raw subtitle tail context, with configurable gating:
  - `wait_for_all_summaries`
  - `start_when_ready`
- [ ] `ARCHITECTURE.md` reflects the real pipeline with a Mermaid diagram and an explicit execution-flow section.
- [ ] OpenRouter is supported through the same alias/config system as LM Studio, but backend choice remains explicit by alias or profile, not hidden automatic fallback.

**Key defaults to lock:**
- One root TOML with sections for APIs, models, roles, execution, extractor, subtitle ingestion, subtitle summary, scene inference, artifact generation, and profiles.
- Alias-selected backend only. No automatic LM Studio-to-OpenRouter fallback in code.
- Separate capable-model aliases by default for subtitle summaries and final TDT authoring.
- `Qan` is treated as `Qwen`.
- V1 backend support is limited to OpenAI-compatible chat-completions providers. LM Studio and OpenRouter are first-class; non-compatible API sections in the copied config must be rejected clearly if selected.

## Assumptions

- `Qan` means `Qwen`.
- A single root TOML file is the source of truth even though the repo currently has `config/api.toml` and `config/models.toml`.
- Alias selection, not automatic fallback, is the desired mechanism for switching between LM Studio and OpenRouter.
- Per-grid subtitle summaries are authored by the capable summary model during preprocessing, not deterministically and not by the small scene-analysis model.
- The stage-1 summary cache should be reusable across reruns when the same config profile, source title, and chunk windows match.
